# sflow 项目配置（<项目名>）

> 本文件是 sflow 工作流的项目级配置。/sflow-start 每次启动都会读取它；项目差异全部收敛在这里，工作流本体保持平台无关。
> 使用前请把各项改为本项目的真实命令与约定。
>
> **先看懂 6 个概念，再看下面的配置**：
>
> - **full（完整流程）**：正规军打法。需求先澄清成规划工件（proposal / specs / tasks，design 按需）→ 压缩成执行契约（**你批准后 AI 才被允许写代码**）→ 按批次实现 → 真实验证 → 代码审查 → 归档合并规格。一切中等以上的功能开发都走它。
> - **tweak（快速路径）**：小修小配。改动 ≤ 4 个文件且纯属配置/文档时，跳过完整流程直接改，收口时仍必须真实验证。
> - **hotfix（快速路径）**：紧急抢修。改动 ≤ 2 个文件，跳过规划工件，只记录意图 + 改动清单，收口必须有真实验证输出。
> - **dp1_lightweight（规划确认轻量化开关）**：true 时，走 full 但需求很简单（一句话能说清）的变更，AI 把"需求确认"与"工件展示"合并为一次确认，少打断你一次；复杂需求不受影响，仍分步确认。
> - **外挂增强（可选）**：配置里的「测试工具 / 审查工具」两节，按需填入项目自己的技能名。**留空不跳过**——自动使用工作流内置默认逻辑（默认深度验证 / 默认代码审查）。规划阶段的质量增强已内置在 /sflow-propose，无需配置。
> - **git_discipline（提交纪律开关）**：默认 `off`——批次完成不强制 commit、不强制先写测试。设为 `on` 后 /sflow-apply 每批次必须走 TDD 红-绿（先失败测试 → 最小实现 → 转绿 → 提交），且开始前工作区必须干净。**与验证无关**：无论开关如何，验证义务与批次回执都缺一不可。
>
> 三条底线不受任何开关影响：AI 不得未经你批准契约就写一行业务代码；任何"通过"必须附真实执行输出；快速路径执行中超出边界自动升级回 full。

## 提交纪律（/sflow-apply）

> `off`（默认）：批次完成不强制提交，也不强制先写测试；批次回执与验证义务仍然必做。
> `on`：每批次必须走 TDD 红-绿（先写失败测试并贴输出 → 最小实现 → 测试转绿 → git commit），
>       且每批次开始前工作区必须干净（`git status --porcelain` 无输出），脏工作区拒绝进入批次。

- git_discipline: off
